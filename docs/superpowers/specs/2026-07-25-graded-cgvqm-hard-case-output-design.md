# A/B 分级困难样本与 CGVQM 精判设计

日期：2026-07-25

## 1. 目标

本次改造将困难样本输出从“每个 segment 一个子目录”调整为可直接供训练器读取的 A/B 分级目录，并将 CGVQM-2 作为候选样本的深度时空精判器。

最终系统必须同时满足：

- 用户只需执行一次 `vfi-hard-miner run --config ...`。
- 训练帧按困难中心独立归入 A 或 B，保留原始文件名。
- A/B 目录内不创建视频、segment 或数字编号子目录。
- 训练数据使用原文件字节复制，不重编码、不使用诊断图代替原图。
- 传统局部误差负责高召回定位，CGVQM-2 负责感知及时序精判。
- 只有数据有效、模型可学习且劣化证据明确的样本进入训练目录。
- 诊断拼图改为两行五列，提高分辨率，并使用 JPEG 控制磁盘占用。
- 项目根目录提供自包含中文 `method.html`，详细解释每一步判定方法。

## 2. 输出数据契约

正式训练输出固定为：

```text
extremely_hard_case/
├─ A/
│  ├─ 原始文件名.png
│  └─ ...
└─ B/
   ├─ 原始文件名.png
   └─ ...
```

A 表示明显的大幅度运动或结构性劣化，包括严重断裂、部件缺失、重影、撕裂和大范围结构扭曲。B 表示确定存在、可用于训练但程度较轻的劣化。阈值边缘样本进入 Review，只写 manifest；正常、无效或不可学习样本进入 Reject。

每个预测中间帧独立分级，并将该中心对应的前帧、GT 和后帧复制到相应等级目录。规则示例：

```text
第 2 帧预测为 A：1、2、3 → A/
第 4 帧预测为 B：3、4、5 → B/
```

因此第 3 帧可以同时存在于 A 和 B。相同等级内部的重叠三帧取并集，同一个目标文件只复制一次。不同等级之间不互相升级，也不去重。

所有目标文件保留源文件 basename。不同源文件映射到同一等级中的相同 basename 时：

- 内容和来源一致：视为重复引用，复用已有文件。
- 来源不同或内容不同：明确失败，不允许覆盖或自动改名。

输入中即使包含多个逻辑视频，也允许它们位于同一个源目录。视频分组和连续性仍由索引阶段依据文件名规则判断，但分组信息只用于推理、窗口和防止跨视频组合，不映射为输出子目录。

训练帧采用临时文件加原子改名的字节复制。复制后校验大小，必要时可启用哈希复核。训练帧不转为 JPEG，不改变编码、色彩或元数据。

## 3. 一键执行与内部阶段

README 和 `method.html` 只推荐：

```bash
vfi-hard-miner run --config configs/my_game.json
```

该命令内部完成：

1. 建立或验证索引。
2. 执行当前插帧模型全量推理和传统高召回评分。
3. 为每个已完成视频组织 CGVQM 候选时间窗口。
4. 执行 CGVQM-2 精判和 A/B 分级。
5. 增量复制已确认的 A/B 原始训练帧。
6. 生成诊断拼图、manifest、分级摘要和 `segments.json`。
7. 校验全部产物后原子发布。

`index`、`mine`、内部 CGVQM refine 和 `finalize` 仍保留为可恢复阶段，但不要求用户手动执行。重复运行时根据执行 ID、配置哈希、模型哈希和阶段状态只补缺失工作，不重复已验证的推理、精判或复制。

一个视频的 main chunk 全部完成后即可进入 CGVQM refine；精判完成后立即物化该视频的 A/B 帧到运行专属暂存区。其他视频可以继续推理。最终发布仍是统一原子切换。

## 4. 高质量训练数据门控

任何 A/B 候选必须依次通过以下四层门控。

### 4.1 输入有效性

- 前帧、GT、后帧均可解码且数值有限。
- 三帧尺寸、通道和编号关系符合配置。
- 帧编号按 stride 连续。
- 排除重复帧、跳帧、镜头切换、菜单切换和明显非连续内容。

### 4.2 模型可学习性

- 排除大面积遮挡、严重出界、不可解释运动和超出当前模型可处理范围的数据。
- `p_solvable` 必须达到接受阈值，默认不低于 `0.55`。
- 可解性灰区只进入 Review，不能进入 B。
- teacher 和 best-of-warp 只提供可解性证据，不定义 prediction 是否错误。

### 4.3 错误真实性

- 必须存在具有空间支撑的合格局部异常区域。
- 排除孤立像素、压缩噪声、普通抗锯齿差异和无持续性的微小数值波动。
- 贴边、前后帧近似静止且具有文字或 UI 高边缘密度的区域降低优先级。
- 传统误差和 CGVQM 结论冲突时进入 Review，不自动进入训练集。

### 4.4 严重度分级

共同接受条件为：

```text
validity = accept
AND in_scope = accept
AND p_solvable >= solvable_accept_at
AND 存在合格局部异常
AND mining_p_wrong >= wrong_accept_at
AND CGVQM 确认可感知劣化
```

建议默认：

- `wrong_accept_at = 0.45`：B 的传统错误下限。
- `severe_wrong_accept_at = 0.70`：A 的传统错误下限。
- `cgvqm_b_error_at = 25`：CGVQM 可感知劣化起点。
- `cgvqm_a_error_at = 50`：CGVQM 明显劣化起点。

CGVQM 使用 error 方向，数值越高代表劣化越明显。初始值对应官方感知尺度的保守起点；A3 首轮必须输出分布和抽检清单，允许仅通过配置调整。A 不能只依赖总分，还必须具有强结构证据、足够大的连续异常，或明确的时间持续性。B 必须是已确认的轻微劣化，不包含阈值边缘样本。

## 5. 传统局部错误检测

对模型预测 `P` 和真实中间帧 `GT` 计算：

```text
RGB 误差   = mean(abs(P - GT), channel)
亮度误差   = abs(Luma(P) - Luma(GT))
缺失边缘   = max(Sobel(GT) - Sobel(P), 0)
新增边缘   = max(Sobel(P) - Sobel(GT), 0)
结构误差   = max(RGB 误差, 亮度误差, 1.25 × 边缘误差)
```

候选区域由两条路径产生：

1. 在结构误差图上取 `max(edge_threshold, candidate_quantile)` 作为自适应阈值，提取具有最小面积和 RGB 支撑的连通区域。
2. 使用多个尺度的滑动窗口发现面积较大但单像素峰值不突出的异常。

局部严重度使用区域均值、top 10%、top 1% 和峰值的鲁棒组合，避免全图平均稀释细长结构：

```text
local_score = max(
  mean,
  0.90 × top_10_percent_mean,
  0.95 × top_1_percent_mean,
  0.85 × peak
)
```

`p_wrong` 保留原始 GT 错误，`mining_p_wrong = p_wrong × priority_weight` 用于降低 UI 类区域的挖掘优先级。

## 6. CGVQM-2 深度时空精判

CGVQM 是基于冻结 R3D-ResNet18 多层特征距离的 full-reference 视频质量方法。本项目使用 CGVQM-2：浅层特征更适合定位局部时空错误，并降低候选精判成本。

### 6.1 候选窗口

- 传统评分先产生高召回候选中心。
- 同一视频中候选中心的上下文窗口先合并，避免重复重建。
- 默认窗口为连续 16 帧，可配置但同一次 run 内固定。
- 只为候选窗口重新生成必要的 prediction 序列；重叠中心只推理一次。
- 参考序列为对应 GT 连续帧，失真序列为当前模型生成的连续中间预测。
- 不跨视频边界构造窗口；首尾不足时采用记录在 manifest 中的确定性 padding。

### 6.2 CGVQM 证据

CGVQM-2 输出时空误差图。每个候选中心记录：

- 中心帧候选 box 内的局部 CGVQM 峰值和 top-area mean。
- 候选前后切片的错误持续性。
- 时间方向均值、峰值和突变程度。
- CGVQM 热区与传统结构异常区域的重叠率。
- CGVQM 原始 error、使用的 pooling、窗口长度、patch 配置和后端。

CGVQM 不单独决定等级：

- CGVQM 高且结构证据强或时间持续性明显：允许进入 A。
- CGVQM 明确可见但未达到 A：进入 B。
- CGVQM 与传统证据冲突：Review。
- CGVQM 低且仅有普通像素误差：Reject。

### 6.3 离线资源与设备

现有 CGVQM 源码、`cgvqm-2.pickle` 和许可证继续由 `third_party/manifest.json` 管理。实施时新增本地 R3D-18 Kinetics 主干权重、来源、版本、许可证、大小和 SHA-256。运行时禁止 torchvision 自动下载。

启动时探测 A3 的 Conv3D、BatchNorm、三线性插值和归一化路径：

- NPU 探针和数值对照通过：使用 NPU 微批次。
- NPU 不支持且配置明确允许 CPU：记录降级原因后使用 CPU。
- 权重缺失、误差图非有限、数值对照不通过或所有后端失败：任务失败，不发布 A/B。

CGVQM 微批次继续受每 worker 的内存预算约束。日志分别报告主模型 inferred/scored 和 CGVQM refined/pending，等待超过 30 秒时输出心跳。

## 7. 模型劣化原因

每个原因都输出 `reason_confidence` 和支撑指标，不允许仅根据总误差贴标签。

- `missing_part`：GT 强边缘在 prediction 中消失，缺失边缘显著大于新增边缘，并排除邻域内的轻微平移匹配。
- `broken_structure`：prediction 相对 GT 出现更多连通块或端点，或者细长结构的有效路径明显缩短。
- `ghosting`：同一区域同时存在比例合理的缺失和新增边缘，并形成近似平行、与前后帧运动方向一致的双轮廓。
- `edge_tearing`：边缘错误与光流突变区域或融合 mask 梯度区域达到明确重叠率。普通边缘差异不再直接触发。
- `blur`：GT 局部梯度和细节能量显著高于 prediction，且邻域匹配排除位置偏移。
- `endpoint_copy`：prediction 与前帧或后帧的局部距离明显小于与 GT 的距离。
- `blend_mask_error`：`warp0` 或 `warp1` 已比 GT 更接近，但 mask 融合后误差显著增加。
- `flicker`：运动补偿后，CGVQM 时间误差在相邻预测中突然出现、消失或明显振荡。闪烁不再由单个三帧样本独立判断。

## 8. 两行五列诊断图

诊断图固定为：

```text
第一行：
img0 | GT | prediction | img1 | 传统结构误差图

第二行：
flow_t0 | flow_t1 | CGVQM 中心帧感知误差 |
CGVQM 时间敏感度 | CGVQM 融合置信度
```

旧第三行删除。默认每格宽度由 `320` 提升为 `480` 像素，整体输出约 `2400 × 560`，保持原图宽高比。所有视图使用一致的候选 box 和标注，便于横向比较。

诊断拼图使用 JPEG，默认 quality `92`，采用 4:4:4 色度采样或等价的高质量设置，避免热力图色块被过度破坏。文件扩展名、编码参数和实际尺寸写入 manifest。训练目录中的源帧仍按原始字节复制，与诊断 JPEG 完全隔离。

## 9. `method.html`

项目根目录新增自包含中文 `method.html`，不加载网络资源或业务图片。页面必须详细说明：

- 三帧输入和 prediction/GT 的角色。
- 输入有效性、可学习性、错误真实性和严重度四层门控。
- RGB、亮度、Sobel、结构误差、连通区域和多尺度窗口的计算方法。
- `p_wrong`、`mining_p_wrong`、`p_solvable` 的区别。
- CGVQM 的 R3D 特征距离、时空误差图和候选窗口。
- 每种模型劣化原因的具体计算证据。
- A、B、Review、Reject 的判定链。
- `123 → A`、`345 → B` 和跨等级重复帧示例。
- 一键执行、断点恢复、复制语义、同名冲突和原子发布。
- manifest 字段以及 A3 本地阈值调节方法。

页面以方法说明和审计依据为主，使用纯 HTML/CSS 流程图和示意图，不嵌入真实训练数据。

## 10. 配置与结果摘要

配置新增独立的 CGVQM/分级参数组，至少包括：

- 是否启用 CGVQM。
- CGVQM-2 校准权重和 R3D 主干权重路径。
- backend、是否允许 CPU 降级。
- clip frames、patch scale、微批次和内存预算。
- B/A CGVQM error 阈值。
- `severe_wrong_accept_at`。
- 诊断 JPEG quality 和单格宽度。

最终 JSON 摘要增加：

- main、CGVQM 和物化阶段计数。
- A/B 的中心数、唯一帧数和复制数。
- Review/Reject 原因分布。
- CGVQM 后端、吞吐、窗口数和错误分布。
- 暂存路径、发布路径和冲突检查结果。

manifest 每条记录增加 `grade`、`quality_gate`、`severity_score`、`reason_confidence` 和完整 CGVQM 证据。配置、模型和阈值变化必须改变 run hash，禁止复用不兼容结果。

## 11. 失败处理

- CGVQM 失败不删除已完成的 main 结果，但 run 返回失败且不得发布训练目录。
- 训练帧复制失败保留推理和精判结果，修复磁盘后只补复制。
- 同名冲突在写入前完成全量规划并失败，不产生部分覆盖。
- 每个视频先写独立临时目录或受控临时文件，全部校验后再原子进入运行暂存区。
- 正式 A/B、诊断和 manifest 全部完成后才执行最终原子切换；失败时保留上一版正式输出。

## 12. 测试与验收

### 数据契约

- `123 → A`、`345 → B`，第 3 帧同时存在于 A/B。
- 同等级相邻或重叠三帧取并集。
- A/B 内无子目录且 basename 原样保留。
- 多视频同目录时不跨视频组成样本。
- 同名同源复用，同名异源失败。
- 训练帧与源文件字节一致。

### 质量与分级

- invalid、out-of-scope 和 solvability 灰区不会进入 A/B。
- A 需要 CGVQM 高严重度和强结构/时序证据。
- B 需要 CGVQM 明确确认但不满足 A。
- 传统与 CGVQM 冲突进入 Review。
- 噪声、UI 抖动、轻微位置偏移和普通抗锯齿差异不进入训练集。
- missing、broken、ghosting、tearing、blur、endpoint copy、blend error 和 flicker 各有正负测试。

### CGVQM 与运行

- 候选窗口跨 batch/chunk 时结果一致，不跨视频。
- 重叠窗口只重建一次。
- CPU 与 NPU 在设定容差内输出一致。
- 权重缺失、非有限结果和不允许的 CPU 降级明确失败。
- 等待时持续输出心跳，断点恢复不重复已完成 refine。
- `run` 与分阶段恢复得到完全相同的 A/B、manifest 和诊断结果。

### 可视化

- 输出严格为两行五列。
- 两张 flow、三张 CGVQM 视图和传统误差图的位置固定。
- 默认单格 480 px，文字和候选框清晰。
- JPEG 编码后热力图和局部结构仍可辨认。
- 训练图片未被 JPEG 重编码。

### A3 验收

- 主模型继续保持大 batch 和内存有界后处理。
- CGVQM 只处理候选窗口，端到端吞吐和候选比例均有明确日志。
- 无超过 30 秒的无解释静默。
- 人工抽检 A 为明显结构/时序错误，B 为确定但轻微错误，Review 不混入训练目录。

## 13. 已锁定决定

- 输出为单层 A/B 目录，不再使用 segment/video 子目录。
- A/B 按中心样本独立分级，跨等级允许共享源帧。
- 训练帧使用原文件复制，诊断拼图使用 JPEG。
- 外部使用一键 `run`，内部阶段只用于恢复和诊断。
- 深度精判采用 CGVQM-2，不另建未经校准的三帧 R3D-LPIPS。
- CGVQM 与传统证据共同决定等级，任何单一指标都不能直接生成 A。
- `method.html` 必须详细披露实际判定算法和证据链。
- 诊断图采用已确认的两行五列布局。
